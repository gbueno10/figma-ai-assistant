## Figma AI Assistant – Separated Architecture

This project is now divided into two well-defined parts:

- **Plugin (frontend)**: remains in the root folder, using @create-figma-plugin to generate the bundle consumed by Figma.
- **Backend service** (`backend/`): a Node/Express API responsible for all OpenAI integrations (design analysis, modifications, and image generation/editing).

This separation facilitates maintenance, makes the plugin lighter, and allows running the heavy processing (AI calls) inside a Docker container.

## Setting Up the Backend (without Docker)

```bash
cd backend
npm install
npm run dev       # ts-node-dev with hot reload

# or for production build
npm run build
npm start
```

### Environment Variables

Create a `.env` file in the `backend/` folder (use `.env.example` as reference):

```
OPENAI_API_KEY=sk-xxxx
PORT=3000
CORS_ORIGIN=http://localhost:3000
```

- `OPENAI_API_KEY`: OpenAI key used by the service.
- `PORT`: port where the API will be exposed.
- `CORS_ORIGIN`: comma-separated list of authorized origins. Leave empty to accept all.

## Running with Docker 🐳

### Quick Start

1. **Configure environment variables:**
   ```bash
   cp backend/.env.example backend/.env
   # Edit OPENAI_API_KEY in backend/.env file
   ```

2. **Start the backend using scripts:**
   ```bash
   # Make scripts executable (first time only)
   chmod +x scripts/*.sh
   
   # Start
   ./scripts/start-docker.sh
   
   # Start with rebuild
   ./scripts/start-docker.sh --build
   ```

3. **Or use Docker Compose directly:**
   ```bash
   docker-compose up -d --build
   ```

4. The API will be available at `http://localhost:3000`

### Available Scripts

```bash
./scripts/start-docker.sh        # Start backend
./scripts/start-docker.sh -b     # Start with rebuild
./scripts/stop-docker.sh         # Stop backend
./scripts/logs-docker.sh         # View logs
./scripts/logs-docker.sh -f      # Follow logs in real-time
```

### Docker Architecture

The Dockerfile uses an optimized **multi-stage build**:
- **Stage 1 (Builder)**: Compiles TypeScript and installs dependencies
- **Stage 2 (Runner)**: Minimal final image with:
  - Node 20 Alpine (lightweight image)
  - Non-root user (security)
  - Configured health checks
  - Only necessary files

📚 **Complete documentation**: See [docs/setup/DOCKER.md](./docs/setup/DOCKER.md) for detailed guide, troubleshooting, and advanced configurations.

## Setting Up the Plugin in Figma

1. Build the plugin (if not already done):
   ```bash
   npm install
   npm run build
   ```
2. In Figma, load the plugin via `manifest.json` as usual.
3. Open the plugin and configure:
   - **Backend URL**: defaults to `http://localhost:3000/api`. Adjust if running on another host or port.
   - **OpenAI API Key** (optional): leave empty if the backend already has the key via `.env`. The field remains available if you prefer to pass the key directly through the plugin.

Settings are saved in Figma's `clientStorage`.

## Available Backend Routes

| Method | Route                    | Description                                |
|--------|--------------------------|-------------------------------------------|
| POST   | `/api/design/analysis`   | Analyzes layout and returns suggestions   |
| POST   | `/api/design/modifications` | Generates instructions to modify design |
| POST   | `/api/images/generate`   | Creates new image based on a prompt       |
| POST   | `/api/images/regenerate` | Regenerates image from an existing one    |
| POST   | `/api/images/edit`       | Edits existing image using a prompt       |
| POST   | `/api/images/analyze`    | Generates descriptive prompt from an image |
| GET    | `/health`                | Simple health check endpoint              |

All routes accept the OpenAI key via the `apiKey` field in the request body **or** use `OPENAI_API_KEY` defined in the container/server environment variables.

## Joint Development

- **Plugin**: continue using existing scripts (`npm run dev`, `npm run build`, etc.).
- **Backend**: `npm run dev` (hot reload), `npm run type-check`, `npm run build`.
- **Integration**: the plugin consumes the backend through the URL configured in the UI; just keep the server running.
